# Правила работы с репозиторием

Эти правила обязательны для любых правок кода — как ручных, так и выполненных
ассистентом.

## Атомарные коммиты по ходу правок

- Коммитьте **по ходу работы**, а не одним большим коммитом в конце.
- Один коммит = одна логически законченная правка: одна фича, один фикс,
  один рефакторинг, одно обновление документации.
- Не смешивайте в одном коммите несвязанные изменения. Если по ходу правки
  появилось несколько независимых задач — разбейте их на несколько коммитов.
- После каждого атомарного коммита рабочее дерево должно собираться и
  запускаться (см. «Запуск» в `README.md`).
- Сообщения коммитов — в стиле [Conventional Commits](https://www.conventionalcommits.org/),
  на английском языке, как в текущей истории: `feat:`, `fix:`, `refactor:`,
  `docs:`, `chore:`, `ci:`.

## Ведение ченджлога

- Каждое заметное пользователю изменение фиксируется в `CHANGELOG.md`
  (формат [Keep a Changelog](https://keepachangelog.com/ru/)).
- Записи добавляются в секцию `[Unreleased]` в момент правки и переносятся
  в секцию с версией при релизе.
- Ченджлог обновляется **в том же коммите**, что и само изменение, либо
  сразу следующим `docs:` коммитом.
- Запись пишется на русском языке и отвечает на вопрос «что изменилось для
  пользователя», а не «какой код я поменял».

## Порядок действий при правке

1. Внести правку и проверить, что проект запускается.
2. Обновить `CHANGELOG.md` в секции `[Unreleased]`.
3. Закоммитить атомарно: правка + соответствующая запись ченджлога вместе.
